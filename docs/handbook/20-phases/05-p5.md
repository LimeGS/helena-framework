The phase everything else exists to feed.

## Lanes

Five adapters across twenty-three profiles, and you choose by naming a
**profile**, never a script. The profile pins the checkpoint and its digest, the training scale and
the model family, so two runs of one profile are comparable.

| Profile | Adapter | Trained at | Reads |
| --- | --- | --- | --- |
| `ink-9um-hybrid-3d2d-screening@1.0.0` | `run_ink_9um.py` | 9.6 µm | a surface volume |
| `ink-9um-hybrid-3d2d-seed{42,43}-step*-screening@1.0.0` | `run_ink_9um.py` | 9.6 µm | a surface volume — one profile per checkpoint of the training run, thirteen besides the one above |
| `ink-canonical-2um-screening@1.1.0` | `run_ink_canonical2um.py` | 2.399 µm | a layer stack |
| `ink-canonical-2um-screening@1.0.0` | `run_ink.py` | 2.399 µm | a layer stack |
| `resnet50-7.9um-scroll1-frags-screening@1.0.0` | `run_ink.py` | 7.9 µm | a layer stack |
| `timesformer-gp-scroll1-screening@1.0.0` and `@1.1.0` | `run_ink_timesformer.py` | 7.91 µm | a layer stack |
| `timesformer-large-scroll1-screening@1.0.0` | `run_ink_timesformer.py` | 7.91 µm | a layer stack |
| `timesformer-scroll5-pherc172-screening@1.0.0` | `run_ink_timesformer.py` | 7.91 µm | a layer stack |
| `ink-3d-dino-guided-diagnostic@1.0.0` | `run_ink_3d_dino.py` | — | a patch manifest |

Two of those cannot be queued and it is better to know why now than at the form:

- **`ink-3d-dino-guided-diagnostic`** is declared `unroutable`. It takes a patch
  manifest and a villa Python root rather than a layer stack, and it writes
  where it is told rather than into an output directory. It runs from the CLI
  until somebody gives it a job shape. The queue refuses it *with that reason*
  rather than routing it to a runner that would fail on the first flag.
- **`strict-text-like-screen-calibration`** declares no adapter and no
  checkpoint. It is a statement about the campaign — a threshold, a calibration
  note — not a lane. Queueing it would run the default adapter with no model
  behind it, so the queue refuses it as "a calibration declaration, not a
  runnable lane".

> **Trap** The training scale in that table is the number to match against your
> render. `timesformer-gp` at 7.91 µm and the canonical lane at 2.399 µm are not
> interchangeable, and nothing downstream will tell you that you mixed them —
> the map will simply be worse.

An adapter the queue has not been taught is refused by name. Falling back to
the default runner is how a TimeSformer lane once came to be handed
`--upstream-dir`, which it has no argument for.

## Fields

| Field | Required | What it is |
| --- | --- | --- |
| `checkpoint` | yes | the weights; the digest is verified before inference |
| `layer_stack` / `tiff_dir` / `surface_volume` | exactly one | the input, named as a P4 job id where possible |
| `source_pixel_um` | | the scale the stack was rendered at |
| `source_slice_um` | | the physical spacing between slices |
| `depth_center`, `depth_centers` | | where in the stack to sample |
| `stride`, `batch_size`, `tile_size` | | throughput |
| `min_valid_ratio` | | how much of a tile must be real data |
| `model_family` | | comes from the profile, not from you |
| `on_degenerate` | | what to do with a map that carries no decision |

> **Trap** `source_pixel_um` is stated, never defaulted. An 8.4% error moves the
> recovered peak by tens of microns. For the 9 µm lane it is required with a
> `tiff_dir` for a concrete reason: pooling has to know what it is pooling from,
> and assuming 2.4 would turn a native 9 µm render into a 38 µm one.

## Where the model code comes from

Two lanes import their architecture from a vendored upstream directory. That
directory is a property of **the host**, read from its environment — not a job
parameter. It used to be a field on the queue form, which made the import path
of the model something whoever queued the job chose.

A worker that does not carry one refuses those two lanes by name, and says which
variable to set.

## Reading the result

A probability map: one float per pixel. Brighter is more likely ink.

It is a **screening output, not a reading**. And before it counts as anything,
[P6](#/docs/phases/p6) asks whether it decided anything at all.

## Traps

> **Trap** A lane is scale-restricted. The 2 µm canonical lane must not be
> routed to an 8.64/9.362 µm cohort without its own control at that scale. The
> profile says so in its own `comparability` note.

> **Note** Maps from a resampling lane are produced at the **training** scale,
> not the source scale. A map from that lane may not be compared pixel-for-pixel
> with one from a native-scale lane.
