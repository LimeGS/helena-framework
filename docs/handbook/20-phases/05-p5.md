The phase everything else exists to feed.

It does not require the phases before it. `tiff_dir` accepts any layer stack
the worker can see, including one downloaded straight from the public buckets
— PHerc0139 was screened this way, from a downloaded 109-layer stack, skipping
P1 through P3 entirely. A panel that greyed P5 out until P4 had run would have
blocked that route.

## Lanes

Five adapters across twenty-three profiles, and you choose by naming a
**profile**, never a script. The profile pins the checkpoint and its digest, the training scale and
the model family, so two runs of one profile are comparable.

| Profile | Adapter | Trained at | Reads |
| --- | --- | --- | --- |
| `ink-9um-hybrid-3d2d-screening@1.0.0` | `run_ink_9um.py` | 9.6 µm | a surface volume |
| `ink-9um-hybrid-3d2d-seed{42,43}-step*-screening@1.0.0` | `run_ink_9um.py` | 9.6 µm | a surface volume — one profile per checkpoint of the training run, thirteen besides the one above |
| `ink-canonical-2um-screening@1.1.0` | `run_ink_canonical2um.py` | 2.399 µm | a layer stack |
| `ink-canonical-2um-screening@1.0.0` | `run_ink.py` | 2.399 µm | a layer stack |
| `resnet50-7.9um-scroll1-frags-screening@1.0.0` | `run_ink.py` | 7.9 µm | a layer stack |
| `timesformer-gp-scroll1-screening@1.0.0` and `@1.1.0` | `run_ink_timesformer.py` | 7.91 µm | a layer stack |
| `timesformer-large-scroll1-screening@1.0.0` | `run_ink_timesformer.py` | 7.91 µm | a layer stack |
| `timesformer-scroll5-pherc172-screening@1.0.0` | `run_ink_timesformer.py` | 7.91 µm | a layer stack |
| `ink-3d-dino-guided-diagnostic@1.0.0` | `run_ink_3d_dino.py` | — | a patch manifest |

Two of those cannot be queued and it is better to know why now than at the form:

- **`ink-3d-dino-guided-diagnostic`** is declared `unroutable`. It takes a patch
  manifest and a villa Python root rather than a layer stack, and it writes
  where it is told rather than into an output directory. It runs from the CLI
  until somebody gives it a job shape. The queue refuses it *with that reason*
  rather than routing it to a runner that would fail on the first flag.
- **`strict-text-like-screen-calibration`** declares no adapter and no
  checkpoint. It is a statement about the campaign — a threshold, a calibration
  note — not a lane. Queueing it would run the default adapter with no model
  behind it, so the queue refuses it as "a calibration declaration, not a
  runnable lane".

> **Trap** The training scale in that table is the number to match against your
> render. `timesformer-gp` at 7.91 µm and the canonical lane at 2.399 µm are not
> interchangeable, and nothing downstream will tell you that you mixed them —
> the map will simply be worse.

An adapter the queue has not been taught is refused by name. Falling back to
the default runner is how a TimeSformer lane once came to be handed
`--upstream-dir`, which it has no argument for.

## Fields

| Field | Required | What it is |
| --- | --- | --- |
| `checkpoint` | yes | the weights; the digest is verified before inference |
| `layer_stack` / `tiff_dir` / `surface_volume` | exactly one | the input, named as a P4 job id where possible |
| `source_pixel_um` | | the scale the stack was rendered at |
| `source_slice_um` | | the physical spacing between slices |
| `depth_center`, `depth_centers` | | where in the stack to sample |
| `stride`, `batch_size`, `tile_size` | | throughput |
| `min_valid_ratio` | | how much of a tile must be real data |
| `model_family` | | comes from the profile, not from you |
| `model_config` | | TimeSformer only, for a checkpoint whose architecture the runner's frozen default does not match |
| `on_degenerate` | | what to do with a map that carries no decision |

> **Trap** `model_config` has no default and is easy to skip, because most
> lanes never need it. `timesformer-large-scroll1-screening@1.0.0` declares
> `model_config_required` — its checkpoint carries an eight-head architecture
> against the runner's six-head default — and without the flag a digest-verified,
> installed checkpoint still could not be run at all.

> **Trap** `source_pixel_um` is stated, never defaulted. An 8.4% error moves the
> recovered peak by tens of microns. For the 9 µm lane it is required with a
> `tiff_dir` for a concrete reason: pooling has to know what it is pooling from,
> and assuming 2.4 would turn a native 9 µm render into a 38 µm one.

## Where the model code comes from

`run_ink.py` and `run_ink_canonical2um.py` import their architecture from a
vendored upstream directory. That directory is a property of **the host**,
read from `HELENA_INK_UPSTREAM_ROOT` on it — not a job parameter. It used to
be a field on the queue form, which made the import path of the model
something whoever queued the job chose.

A worker with the variable unset refuses those two lanes by name rather than
guessing. The 9 µm lane needs no such variable: it runs in its own container,
grafted from a separate frozen environment because its inference stack pins a
torch version five major releases apart from the one the ordinary ink worker
carries — see [deploys](#/docs/operations/deploys) for how the images are
built. The DINO lane takes its dependency the same way, but as a job
argument, `--villa-python-root`, rather than a host variable — one more reason
it runs from the CLI rather than through the queue.

## Reading the result

A probability map: one float per pixel. Brighter is more likely ink.

It is a **screening output, not a reading**. Before it counts as anything, the
adapter assesses its own map and writes a verdict into the P5 receipt:
`ALIVE` (it varies, and can go to screening), `DEGENERATE` (it carries no
decision) or `EMPTY` (no valid pixels). A job that finishes with no verdict
recorded at all is failed too — a missing check must not read like a passed
one. [P6](#/docs/phases/p6) covers the three thresholds and what each verdict
does to the job.

## In the panel

The tabs, in that order: **Maps**, what P5 actually produced, read live from
the job queue; **Runs**, which indexes the legacy `CX_RUNS` receipt tree on
disk and is empty on a fresh install, because a screening queued through the
fleet writes its map wherever the worker named and never enters that index;
**Models**, the lane profiles, their adapters and the method registry's record
of each, cross-referenced so a profile with no adapter or a method with no
profile is visible as such; **Profiles**, the frozen declarations, read-only;
and **Run**, which queues a lane.

Maps is sortable by when it ran, scroll, surface, lane, state, verdict, p50,
p99 and spread, and filterable by job, scroll, surface, lane, job state or
verdict. A map's picture is rendered on the server, on a percentile stretch
printed under it — never the raw array, because a viewer that silently
rescales is exactly how a map that carries no decision comes to look like one
that does. Behind it: `GET /api/ink/maps`, `GET /api/ink/maps/{job_id}`,
`GET /api/ink/maps/{job_id}/render.png` and `GET /api/ink/lanes`.

A checkpoint reaches the models volume through `POST /api/models/download`,
never by writing into it from outside: the panel is the only process allowed
to place one, and a `.pth` or `.pt` pickle is fetched only against the digest
the caller states as `expect_sha256` — a mismatch is deleted, not installed.
`scripts/harness/install_declared_weights.py` drives that endpoint once per
checkpoint a deployment's profiles declare and does not yet have. A
from-scratch reproduction of the 9 µm lane, driven only through this API
against public data, is at `docs/public-control/REPRODUCE.md`.

## Traps

> **Trap** A lane is scale-restricted. The 2 µm canonical lane must not be
> routed to an 8.64/9.362 µm cohort without its own control at that scale. The
> profile says so in its own `comparability` note.

> **Note** Maps from a resampling lane are produced at the **training** scale,
> not the source scale. A map from that lane may not be compared pixel-for-pixel
> with one from a native-scale lane.
