---
title: P6 — Liveness
summary: Did the map decide anything, or is it a flat field with a filename?
---

Not a phase you queue — it has no lane, no parameters, and is not in the
queueable set. The P5 adapter assesses its own map and writes the verdict into
the P5 receipt; the worker then fails the P5 job if it finds none.

## What it asks

A detector handed an unusable input still produces a map. A constant array, or a
flat field at 0.51, is a perfectly valid float image. Nothing about the file says
it carries no decision.

Three criteria, and **any one** failing makes the map `DEGENERATE`:

| Criterion | Threshold |
| --- | --- |
| spread | `p99 − p50 ≥ 0.05` |
| variation | `std ≥ 0.02` |
| not piled at the middle | at most 90% of valid pixels within 0.05 of 0.5 |

That third one is why the flat field at 0.51 fails: it sits inside the
near-half band.

Which pixels count: the validity mask if there is one, otherwise **strictly
positive values only**. So an all-zero map comes out `EMPTY`, not `DEGENERATE`.

## The three verdicts

| Verdict | Means |
| --- | --- |
| `ALIVE` | the map varies; it can go to screening |
| `DEGENERATE` | the lane produced no decision |
| `EMPTY` | no valid pixels at all |

> **Trap** `EMPTY` is not a milder third outcome. It is refused exactly as
> `DEGENERATE` is — same marker, same message, same exit — and P7 refuses both
> identically, because it admits only `ALIVE`.

## What happens to the job

Exit 3, and the job ends **`failed`** with `refused` set to the reason. An
operator scanning the queue sees a red row, not a special one — but the row
carries a refusal rather than an error, which is a thing you can filter for.

> **Trap** Exit 3 only happens when `on_degenerate` is `fail`, which is the
> default. With **`warn`** the adapter prints a warning and returns 0: the P5
> job **succeeds**, the DEGENERATE verdict is recorded on a job that passed, and
> P7 refuses it later. That knob is a P5 parameter and it changes what a green
> row means.

## The rule this exists for

A P5 job with **no** liveness verdict at all is failed. Storing null read
exactly like a lane that had been checked and found alive, which is how three
adapters went a long time without the gate and nobody saw it.

> **Trap** One adapter still trips this by construction: `run_ink_3d_dino.py`
> declares no receipt, so nothing is found, the verdict is null, and the job is
> failed under that rule. It is `unroutable` anyway — but that is the trap
> firing on a lane rather than on history.

## Where else the gate sits

Two places, not one:

- **after a run** — the verdict on the P5 receipt, read by
  [P7](#/docs/phases/p7) from the job row before it will fetch the map;
- **before routing** — a lane's positive control must be alive before that lane
  may be routed to a target at all. It fails closed.

> **Note** The verdict does **not** reach the vetting card. The card is
> vendored byte for byte and the worker puts its additions beside it, not
> inside. Liveness lives on the screening; the card is the adjudication.

If you hand P7 a map by `map_path` rather than by `screening_of`, it looks for
one specific receipt filename — the generic adapter's. A TimeSformer, canonical
2 µm or 9 µm map handed over by path is refused as "a map with no receipt" even
though its verdict exists. Use `screening_of`, which reads the verdict off the
job row.
