---
title: P4 — Surface volume rendering
summary: Sample the CT through the sheet, into a numbered stack of layers.
---

The step that turns geometry into something with grey values in it.

The panel gives P4 no view of its own: with no `Artefacts` tab to sit beside
`Run`, the tab bar never renders, and the queue form is the whole page.

## Lanes

| Lane | Runs | For |
| --- | --- | --- |
| `vc-render-tifxyz` | the VC3D renderer | the ordinary case — any scroll, reading a tifxyz directly |
| `chunk-gather` | a chunk gatherer | a legacy PPM segment, bridged through a named rescan's own volume — any scroll, though only validated (r = 0.89 against an official ink map) on PHerc0332 |

`chunk-gather` was renamed from `scroll3-chunk-gather` once its renderer
stopped hardcoding one rescan's volume key, array shape and voxel size and
started reading them from the volume the job names. A job queued under the old
name still runs unchanged — it is the lane that changed, not where it writes.
Which lane to pick is about the input you hold, not the scroll: a tifxyz (a
path, or the id of a sheet P3 flattened) goes to `vc-render-tifxyz`; a legacy
PPM goes to `chunk-gather`. One measured point on the default lane: 33 slices
at 1380x1380 rendered from a flattened sheet in 17.9s on one consumer GPU.

## Fields

The default lane requires `segmentation` (or `flattened_surface`), `volume`,
`scale` and `group_idx`. The chunk-gather lane requires `ppm` and
`volume_key` — the rescan's own OME-Zarr key under the open-data bucket, not
the `volume` field below, which is a path on disk. The phase itself declares
nothing required — enforcement is per lane.

| Field | Required | What it is |
| --- | --- | --- |
| `segmentation` / `flattened_surface` | **one of** | a directory the worker can see, or the P3 output by id |
| `volume` | **yes** | where chunks are staged; a cache when `remote_url` is set |
| `scale` | **yes** | pixels per level-g voxel; a float |
| `group_idx` | **yes** | resolution level; 0 is full |
| `remote_url` | | the OME-Zarr to stream; enables prefetch |
| `num_slices` | | how deep the stack goes |
| `slice_step` | | spacing along the normal, **in voxels**; a float |
| `source_voxel_um` | | the physical scale |
| `cache_gb` | | how much disk the staged chunks may use, in GB |
| `flip_normals` | | which way the slices go — see below |
| `tif_output` | | defaults to `layers/` in the run directory |
| `zarr_output` | | **no default**; an extra export, TIFFs are written either way |
| `keep_local_layers` | | do not delete the local copy after publishing |
| `allow_local_layers` | | deliberate single-machine run |

Naming `flattened_surface` **also requires** `flattening_id`, `p3_job_id` and a
64-hex `flattened_artifact_sha256`. Those are server-derived, so in practice this
means queueing through the path that fills them rather than by hand.

`chunk-gather`'s own fields, none of them shared with the default lane:

| Field | Required | What it is |
| --- | --- | --- |
| `volume_key` | **yes** | the rescan's OME-Zarr key under the open-data bucket; the wrong rescan renders a plausible stack of the wrong scroll |
| `layers` | | how many layers to write |
| `spacing` | | distance between sampled slices, in voxels |
| `out_dir` | | where the job writes; defaults to the run directory |
| `concurrency` | | how many chunks to fetch at once |
| `stripe` | | render one horizontal band only, for a cheap look first |
| `max_gb` | | upper bound on what the job may write |

> **Note** The two lanes have never been compared on the same surface: the
> r = 0.89 figure above is `chunk-gather`'s own and does not transfer to the
> default lane. Within the default lane, rendering from `flattened_surface` is
> also one interpolation further from the scan than rendering the certified
> surface directly through `segmentation` — flattening resamples it — and
> those two have not been compared either. `vc_render_tifxyz` has its own
> `--flatten` flag; Helena does not use it, and flattening as its own P3 step
> instead is what gives the sheet a receipt and keeps it reusable across
> renders.

> **Trap** `source_voxel_um` is hidden from the form but is **not**
> unconditionally filled in. The queue resolves it from the frozen catalogue
> for a scroll P0 holds an entry for, and refuses the job outright when it
> cannot — so an ordinary job cannot silently render at the renderer's
> 1.0-voxel default. A scroll outside the catalogue is the exception:
> PHerc0139, the public control used below, is one, and its jobs must state
> the value by hand or be refused. This resolution runs inside the panel's
> queue endpoint; a job built directly against the job store skips it, and
> there `source_voxel_um` really is left unset — the renderer then reports
> *"Voxel size: 1.0 (no metadata found)"* and carries on, and P5 cannot derive
> its depth pitch from the render, so the TimeSformer lane refuses rather than
> guessing. A P4 that "worked" that way blocks P5.

> **Trap** `segmentation` must be visible **to the process that opens it**, not
> to you. The panel and the worker are different containers, often on different
> hosts. A path that exists on the host and is not mounted in the container gets
> one line — `Error loading` — from a renderer that then exits **zero**. Helena
> checks it and says which of **two** it is: missing (a mount), or unreadable (a
> permission). That check runs after the claim, so it costs one attempt.

> **Cost** With no `artifact_store` and no `allow_local_layers`, the job is
> refused — a stack on one worker is lost with that worker. With a store, the
> local copy is **deleted** after publishing unless you pass
> `keep_local_layers`.

Ceilings that will refuse a job outright: `num_slices` 100000, `slice_step`
10000, `cache_gb` 4096, `scale` 1024, `group_idx` 64 on the default lane;
`spacing` 100000, `concurrency` 256, `stripe` 65536 and `max_gb` 4096 on
`chunk-gather`.

A job also has a wall-clock limit set by the deployment — six hours by
default — shared with P5, P7 and P9 on the same GPU worker. A job that runs
past it is marked failed, with the timeout named in the reason, rather than
left running.

### Do not render twice for orientation

A reversed slab is the far side of the sheet first, and it matters: on the
PHerc0139 community mesh the renderer's default is the opposite of theirs, and
the ink map came out at r = 0.09 against theirs and r = 0.885 the other way.

The trap is what you do about it. Rendering the same window twice — once with
`flip_normals` and once without — costs a whole second render and buys nothing,
because a detector that infers in **both directions** already gives you both
answers from one stack. Measured on the same window:

| Compared | r |
| --- | --- |
| flipped render, forward map **vs** unflipped render, reverse map | **+1.0000** |
| flipped render, reverse map **vs** unflipped render, forward map | **+1.0000** |
| forward **vs** reverse, same render | +0.3465 |

The first two rows are the point: flipping here is *exactly* choosing which of
P5's two outputs to read. The third row is why the choice still matters — the
two directions are genuinely different maps, and one of them is the sheet.

> **Cost** Decide orientation by reading P5, not by rendering again. A
> two-orientation sweep done with two renders spends twice the GPU time for an
> answer one render already contains.

## Reading the result

Before P4 will call a job successful it looks at what it wrote:

- the count matches `num_slices` exactly, when one was asked for;
- the filenames are numeric and the indices are exactly `0..n-1`;
- the middle slice is not a constant.

Without `num_slices` only the contiguity holds. A stack with the right count but
non-numeric names is refused too.

The last one matters most. A render whose surface fell outside the cached
region, or whose scale was wrong, writes the requested number of files and every
one is flat: exit 0, 33 files, nothing in them. The middle slice is checked
rather than the ends because the ends of a stack can legitimately fall off the
lamina.

> **Note** The renderer reports *"Voxel size: 1.0 (no metadata found; override
> with --voxel-size)"* and carries on when the volume has no metadata. Helena
> passes `source_voxel_um`, so the render and the depth arithmetic use the same
> number — but a hand-run render will not, unless you pass it.

## Traps

> **Trap** A stack that exists only on the worker is lost with the worker. P4
> refuses to call a render a success when there is nowhere to publish it, unless
> you deliberately pass `allow_local_layers` for a single-machine run.
